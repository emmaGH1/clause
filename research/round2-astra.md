# Round two · Give the judge the last panel

**Pick Hold the Reveal. I withdraw Exact Change as the default.** A judge can open the teaser, read the last balloon and look for the spoiler with their own eyes. Then they can choose a different ending and make the agent earn a different answer. That is a stronger thirty-second challenge than asking them to trust a grocery optimizer, understand two QA workspaces or read a library timetable.

This is a design recommendation. The sources below establish what the sites and tools expose. Statements about demand, reliability, build time and judging are my inferences. No authenticated Kane run, shopper interview or artist trial was conducted for this review.

## Hold the Reveal · The entry I would submit

**When a comic artist taps the last balloon readers may see, they get a shareable teaser that preserves the line and hides the next reveal at the tested reader width, and TestMu gets Kane’s reader-view evidence driving and checking an editor agent’s cut.**

**First 30 seconds.** At 0–8s the judge reads an actual short strip and taps the line before a wordless reveal. At 8–18s they inspect a labeled previous run: the final word disappears below the cut. One swipe shows the corrected public teaser and they can read the word. At 18–30s they choose a different final balloon and start a fresh proof. Show its chosen line, width and first incoming Kane step as available. A slow worker can take longer than the pitch. Keep the earlier frames attached to their original run.

**The loop.** Use one original or permissioned vertical comic with real text overlaid on art, an immutable revision URL per cut and a single declared reader width. Lettering wraps in the published reader. The artist supplies the exact final line and a small reference image of the next reveal. The worker runs an editor agent with those references and Kane’s evidence.

1. The editor estimates a cut at the nearest gutter from the source layout. Build a public draft. Each candidate uses the real typography and reader layout. Never insert a deliberate clipping bug.
2. On the authenticated VM worker run `kane-cli run "Go to <revision-url>, scroll the comic reader to its end, and store the last fully visible balloon text as last_line" --agent`. Replace the URL with the immutable draft. Capture the terminal reader screenshot from the run evidence. Check the actual rendered reader width against the declared width. Stream progress to the Vercel page through a polled job record. [Agent commands and evidence](https://github.com/LambdaTest/kane-cli#readme)
3. Pass the editor the screenshot, the target line, the reveal reference and the parsed `run_end.status`, `final_state.last_line` and exit code. A successful extraction merely means the observation ran. Inspect the pixels for the complete lettering and balloon outline and for any visible portion of the specified reveal. DOM text alone can survive clipping. If the final balloon starts above the terminal frame, capture its preceding frame too. Record the observed defect beside the original image.
4. A clipped balloon moves the boundary down. An exposed reveal moves it up. Try the nearest unused candidate in that direction, publish a new revision and repeat the same Kane objective. If both defects coexist or no available cut separates the two, give the artist the conflicting frame and ask for a lettering or layout edit. Bound the search to two revisions. Missing or ambiguous evidence leaves the cut unverified.
5. Release the passing immutable URL with target line, actual width, time, run reference and reader frame. The judge can reopen it and compare it with the source. The claim covers the visible teaser at that width. A recorded run can demonstrate the loop during an outage, but cannot certify a new choice.

**Hour one is a decision, not UI time.** First 15 minutes: put one rights-cleared strip with real lettering and two plausible endings on Vercel, authenticate the worker and run the documented command. Next 30: capture a clean ending, a naturally too-short cut and a cut exposing part of the wordless reveal. Blind the editor to candidate coordinates, filenames and expected verdicts. Require all three classifications to agree with visual inspection, including partial exposure. Last 15: let the editor choose a new cut from one failed frame and obtain a fresh passing Kane frame at the same width. Keep the artifacts. Kill the pick if art rights, screenshot access, repeatable width, visual discrimination or the second run fails. The visual branch and runtime are unproven.

**Cut list and clock.** One strip, two selectable endings, one reader width, one public reader. Cut uploads, accounts, translation generation, social-platform previews, multi-device certification, Photoshop integration and general-purpose cropping. By halfway, a logged-out phone on the deployed Vercel URL must initiate a fresh VM job, open the resulting teaser and inspect both attempts. At 75% freeze features and finish the film, README and fallback. Aim to submit at 90%.

**Why a judge might remember it (inference).** August drew 69 entries. November’s field size is unknown. Onred asked the judge to evaluate a code repair on the builder’s own cart. Here the judge makes an editorial choice before the run and leaves with something another person can read. The shot to put in the winners post is the same balloon across two real reader frames, with the missing word circled in the first and the spoiler still concealed in the second. A generic browser harness could supply pixels too. Kane earns its place by opening each public revision, returning inspectable evidence to the editor and independently checking what the editor changed. If the demonstration works just as well with a source-image crop, Sol’s criticism wins and this entry should die too.
